# 日记本 · 深圳湾日记管理入口

日记本是深圳湾日记的 Flask 管理入口，负责账号登录、日记功能，以及认知工作区的子服务接入。启动入口为 `app.py`，由 Waitress 提供 HTTP 服务；日记数据库与 OSS 每日备份由同一个进程管理。深圳湾日记可独立运行，不导入或依赖最外层主站项目；认知工作区保留在 `../../认知工作区/` 内，使用独立 HTTP 进程、身份和数据。

## 启动和访问

```powershell
python -m pip install -r requirements.txt
python app.py
```

仓库不包含已注册账号和私人数据。首次运行会建立空账号存储，请在注册页创建自己的账号；也可以按项目根目录说明初始化一个虚构演示账号。

内置的两份个性欢迎音频位于 `assets/welcome-audio/`，首次运行会复制到 `data/music-data/`，已有同名音频不会覆盖。新注册用户默认启用声音，并从全部欢迎音频中等概率随机播放；用户自己的开关和音频配置仍保存于各自数据目录。音频目录与备份范围维持原约定。

默认监听 `0.0.0.0:8081`：

| 页面 | 地址 |
|---|---|
| 日记主页（建议收藏） | `http://服务器IP:8081/` |
| 登录 | `http://服务器IP:8081/login` |
| 注册 | `http://服务器IP:8081/register` |
| 认知工作区（需先登录） | `http://服务器IP:8081/cognitive/` |

浏览器标题包含“日记本 · 深圳湾日记”。8081 端口的根路径 `/` 就是日记主页，未登录时自动进入 `/login`，登录后返回 `/`。顶部“日记本”和“认知工作区”提供同窗口跳转，工作区也可返回日记本；切换前请保存正在编辑的日志。独立访问时不带主站前缀。程序默认不占用 80 端口。

认知工作区由 `../identity/subservices.json` 指定，首次访问时核验服务身份与部署凭证，匹配则复用，端口空闲才启动；不接管不匹配的服务。工作区默认只监听回环地址 `127.0.0.1:8766`，日记本停止后已确认的工作区继续运行。它通过受保护的网关接收登录用户标识，不共享日记本 Cookie，也不会自动读取或注入日记原文。工作区自己的代码和数据可相对独立发布。

自定义地址和端口：

```powershell
python app.py --host 127.0.0.1 --port 8081
```

也可以使用环境变量 `DIARY_HOST`、`DIARY_PORT`；命令行参数优先。通过服务器公网访问时，需要在操作系统防火墙/云安全组中允许所用端口。

## 登录有效期

- 登录成功后有效期固定为 **24 小时**。页面刷新、编辑和后台状态查询均不延长有效期。
- 未登录或过期后访问收藏的 `/`，自动进入 `/login`，登录成功再回到日记主页。
- 已打开的页面到期后禁止编辑并自动进入登录页；每 15 秒额外验证服务端状态。切回标签页、窗口恢复焦点或浏览器恢复历史页面时，先验证登录再开放编辑。
- 临时断网或无法确认服务端状态时显示遮罩并暂停编辑，连接恢复后重新验证。到期跳转不会自动保存未提交内容，请在有效期内保存日记。
- 服务端也拒绝过期会话的写入请求，不依赖浏览器计时器；接口返回 401，页面会立即处理。
- 本版改用独立 Cookie `diary_session`，路径为 `/`。升级后旧登录状态需要重新登录一次。

## OSS 备份

配置文件为数据目录中的 `oss_backup_config.json`（默认 `data/oss_backup_config.json`），密钥从 `OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET` 环境变量读取。默认禁用备份；可从 `config-examples/oss_backup_config.example.json` 复制配置，再填写自己的 Bucket 和独立前缀、按需启用。配置和版本规则详见 [OSS备份说明](OSS备份说明.md)。

成功备份保留最近 7×24 小时内的全部版本，并至少保留最新 7 个；仅在新备份及全部将保留版本校验成功后，才逐份删除数量大于 7 且年龄严格超过 7×24 小时的最早版本，异常时保留旧版本。

页面文字统一为“备份成功”或“备份失败”，绿色/红色规则仍按距上次成功是否超过 30 小时判断。

## 通过主页主服务访问

可选的外部主站可通过 HTTP 核验深圳湾日记的整体组身份、角色与层级能力，并将整体入口反向代理到自己的挂载路径。主站不包含在本开源仓库中，独立运行日记本无需安装主站。服务管理器应复用身份匹配的已运行服务，避免接管端口上的其他程序。认知工作区由日记本管理入口接入。

主站默认监听 80；通过主站新启动的日记本只监听 `127.0.0.1:8081`。也可以先独立执行 `python app.py --host 127.0.0.1 --port 8081`，再启动主站接入。主站不会改变已有服务的监听地址。通过主站访问时，页面、登录跳转和接口位于 `/shenzhen-bay-diary/` 下，认知工作区位于 `/shenzhen-bay-diary/cognitive/`，不会跳转到内部端口。旧 `/diary/` 与 `/diary/cognitive/` 保留兼容。

日记本自身支持来自回环地址的 `X-Forwarded-Prefix`，不指定前缀时仍使用根路径，独立部署无需主站包装脚本。非本机请求传入此前缀会被忽略。主站代理会把日记会话 Cookie 的 Path 改为当前挂载前缀；其他代理也应按其挂载位置调整 Cookie 路径。

版本内的全部持久文件默认在 data/ 中，包括账号、日记、音乐、配置和备份状态。项目身份另放在版本目录同级的 identity/，不随普通版本替换。迁移机器需同时复制 identity 和含正式 data 的版本目录，并重新配置环境变量。

## 稳定服务身份

无需登录访问 `GET /__service__/identity`，独立启动和代理部署都提供此接口：

```json
{
  "service_id": "urn:uuid:c6e65645-aa71-479b-8f7e-fdd7e9efaeea",
  "identity_protocol": 1,
  "app_version": "t11",
  "ready": true,
  "service_name": "深圳湾日记",
  "service_role": "service-group",
  "gateway_service_id": "urn:uuid:e56ef2d9-4867-48f7-8ab4-662de0a790c3",
  "gateway_name": "日记本",
  "services": [
    {"name": "日记本", "role": "gateway", "mount": "/"},
    {"name": "认知工作区", "role": "workspace", "mount": "/cognitive/"}
  ],
  "capabilities": ["forwarded-prefix-v1", "service-hierarchy-v1"]
}
```

组 ID、管理入口组件 ID 和身份协议版本保存在 `../identity/service.json`，`utils/service_identity.py` 负责读取与校验。原日记本 ID 保留在 `gateway_service_id` 中，主站匹配的是新的整体组 ID 及层级信息。身份文件缺失、损坏或协议不兼容时启动失败，不会自动生成或回退为代码中的另一个 ID。正常升级、改标题、换域名、搬迁和修改端口时都不要重新生成这些 ID。业务版本由 `app_version` 表示，不参与身份匹配。`identity_protocol` 是独立的身份协议版本，未来协议扩展应保留版本 1 的兼容性或明确协商版本。

HTTP 200 且 `ready=true` 表示应用可以接受请求；HTTP 503 且 `ready=false` 表示该身份的应用未就绪。此状态不保证 OSS、AI 等外部系统可用。接口不触发登录、创建用户目录或启动备份，不公开 PID、数据路径或密钥。

公开项目 ID 不是防伪认证，也不区分同一项目的不同部署或数据实例。管理器只读取并核验，日记不维护调用方白名单或主站地址。未来若增加身份认证，应使用部署私钥与挑战验证；不能把秘密写进开源代码。

## 数据目录与代码升级

本项目可独立运行，无需主站，但需保留项目自己的 identity 目录。默认目录结构为 identity/service.json 与 current/app.py、current/data/。版本目录也可叫 t12，数据仍位于 t12/data，身份仍从同级 identity 读取。

| 数据根目录内的路径 | 内容 |
| --- | --- |
| `auth/users.json` | 账号与密码哈希 |
| `user-data/` | 用户映射、日记数据库（含在途任务与属性当前状态）、设置、导出的 Excel |
| `music-data/` | 音乐、欢迎语音频 |
| `oss_backup_config.json` | OSS 部署配置 |
| `.backup-runtime/` | 备份调度状态与成功记录 |
| 旧提示词 JSON（已有部署可能保留） | 历史配置；日记页面已不使用，开源仓库不附带这些文件 |
| `.session-secret` | 默认持久登录签名秘密；也可由 `FLASK_SECRET_KEY` 提供 |
| `.subservices/` | 下属认知工作区的部署凭证、日志 |

路径由 `utils/paths.py` 定义。DIARY_DATA_ROOT 默认 data，相对值基于版本目录解析；DIARY_IDENTITY_DIR 默认 identity，相对值基于版本目录的父目录解析，两者都支持绝对路径，不依赖终端当前目录。身份目录必须在版本目录和业务数据目录之外。开发版本可使用自己的 data 和不同端口，不能让两个版本同时操作同一份正式 data。

新安装时没有备份配置，应用默认不启动 OSS 备份。迁移后的实例沿用 data 中已有的备份配置、密钥和状态，不重置成功记录。已有的环境变量仍需由运行账号提供。

认知工作区保留自己的数据目录，日记本 OSS 备份范围没有扩展到工作区。迁移时需同时保留工作区的代码、身份与数据，并独立备份。通过日记本登录的账号按 `user_map.json` 中的用户编号分配工作区数据；开源仓库不附带已注册账号、映射或工作区对话。详见[整体部署说明](../../README.md)。

## 在途任务与待提升属性

旧系统/用户提示词、AI 分析和续聊的界面及接口已移除，由“在途任务”文本框替代。文本框默认四行，可上下拖动大小，和右侧日记字段共同参与顶部“保存日志”。

两栏是跨日期的当前状态，不是每日历史：`get_log` 在任意日期都返回最新保存内容，切换日期保留本页未保存的两栏草稿，刷新页面则重新读取服务器保存值。每用户 `diary.db` 的 `logs` 表仍保存每日记录，`user_state(key, content)` 统一保存 `in_flight_tasks` 与 `improvement_attributes`；一次保存使用同一 SQLite 事务，未提供的状态字段保持原值，显式空文本表示清空。

升级后第一次打开用户日记时，将旧 `待提升属性.txt` 只导入一次；保留原文件，后续读写以数据库为准。完整 SQLite 在线备份覆盖这两项当前状态，恢复时无需额外文本文件。旧程序不能读取新状态表，回退版本前应另行导出新增内容。

## 计划与摘要的默认继承

选择尚无日记记录的日期时，“计划与摘要”显示该日期之前最近一个已保存日期的内容，可跨过漏写的日期；不使用后面的日期或未保存的草稿。没有更早记录时显示空白。继承只影响本次读取的显示，不自动创建日期记录、不改动其他字段或历史内容，也不需要零点定时写入。

点击“保存日志”时，页面当前显示或修改后的计划与其他日记字段一起保存到所选日期，即使没有改写也会固化；以后更早日期的计划变化，不影响这一天。已有记录的日期始终使用自身保存值，包括空白；前一个已保存日期的计划为空时，也继承空白，不跳过它恢复更早的非空计划。

此功能沿用 `logs.plan_summary`，不新增数据库表或列。现有数据库中的日记行均视为已初始化，包含历史导入的空行；不根据计划为空推断“未保存”，也不自动修改这些历史记录。各用户只从自己的数据库继承。“在途任务”与“待提升属性”仍按上述跨日期当前状态规则显示。

## 升级与发布

普通升级先停止日记进程，将 current/data 完整备份到版本目录之外，再归档或删除旧 current。复制新版本并命名为 current，用正式备份完整替换新版本的测试 data（不混合合并），按需安装依赖后启动。identity 保持不动。新版本需遵守稳定身份和版本内 data 的路径约定；未适配的历史版本不能直接替换。尽量保持 data 兼容，但允许特殊版本调整结构并单独设计迁移，不预设通用数据迁移框架。

作为开源项目发布时，提供 identity 和不含真实 data 的版本代码；data 包含账号、密钥和私有记录，已被 .gitignore 忽略。历史归档也可能带有旧数据，不应直接公开。业务版本 app_version 和代理 capabilities 由各版本代码声明，不属于永不变的项目 ID。
