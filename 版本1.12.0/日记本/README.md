# 日记本管理入口与版本部署

日记本是深圳湾日记的管理入口，负责账号登录、日记功能以及下属认知工作区的接入。主页只管理深圳湾日记这一整体服务组；认知工作区由日记本按自己的配置管理，代码、身份和数据留在 `../认知工作区/`，可相对独立发布。

```text
深圳湾日记/日记本/
├─ identity/
│  ├─ service.json       深圳湾日记组身份及日记本组件身份，不随业务版本更新
│  └─ subservices.json   认知工作区的身份、回环地址和相对启动路径
└─ current/             当前部署的完整版本
   ├─ app.py
   ├─ requirements.txt
   ├─ assets/           内置欢迎音频（随代码发布）
   └─ data/             运行时创建；账号、用户数据、音乐、配置和备份状态
```

主站固定启动 `current/app.py`，HTTP 核验深圳湾日记的组身份、角色及层级能力后代理 `/shenzhen-bay-diary/`；旧 `/diary/` 保留兼容，不扫描版本目录。日记本自身读取 identity，不依赖“主页”的代码或配置。登录后可从顶部切换到认知工作区，工作区提供返回日记本的入口。端口是部署位置，不是服务身份。

部署使用 current/data 保存运行数据；开源仓库不附带账号、日记、工作区对话、密钥或历史部署归档。需要自行归档旧版本时，请存放在仓库之外，并保护其中的运行数据。

## 普通版本升级

1. 停止日记进程并确认完全退出。主站可以继续运行；只关闭主站不会停止日记。
2. 将旧 current/data 完整复制到一个临时备份位置，放在待替换的 current 之外。确认备份包含账号、日记、音乐、配置和隐藏的 .backup-runtime。
3. 把旧 current 删除或归档。归档名由你选择，已有同名存档时不要覆盖。
4. 复制研发完成的版本文件夹，例如 t12，改名为 current。目录应为 current/app.py，不是 current/t12/app.py。
5. 用正式备份完整替换新版附带的 data。不要把测试数据与正式数据合并，也不要误删 identity。
6. 新版依赖有变化时，用日记所用 Python 安装 current/requirements.txt。
7. 启动新版日记，确认原账号能登录、历史日记和备份状态正确，再处理临时备份。

主站保持运行时，从 current 中执行：

```powershell
python app.py --host 127.0.0.1 --port 8081
```

主站会自动重新核验并恢复 `/shenzhen-bay-diary/` 和旧 `/diary/`。日记本停机期间主页正常，这两个入口暂时返回 503。主站不会在你升级时自动重启日记本。也可以重启主站，让它在启动时拉起日记本，两种方式选一种。认知工作区是独立进程，日记本停止不会同时关闭已接入的工作区；修改其部署时需单独管理。

各版本应保持服务身份接口及启动参数兼容，使用版本内的 data。尽量保持 data 内部结构兼容；需要改结构的特殊版本，单独提供迁移与回退步骤，不在这里强制规定所有未来业务数据结构。

## 身份、开发与独立部署

`identity/service.json` 保存深圳湾日记整体的公开组身份，`gateway_service_id` 保留日记本组件原有的身份。普通升级、版本目录改名、换域名或换端口都不改这些 ID。业务版本号留在各版本代码中。主站保存预期组 ID，通过运行服务的身份接口核验，不靠磁盘文件存在就认定端口属于深圳湾日记。认知工作区的预期独立 ID 与入口记录在 `identity/subservices.json`，路径相对此配置解析。

独立部署也带上 identity 和版本代码，不需要“主页”；使用完整工作区功能时保留同级认知工作区。开发目录可叫 t12，使用自己的 t12/data 和测试端口；默认读取同级 identity。需要在其他目录运行时，可用 DIARY_IDENTITY_DIR 指定身份目录。数据路径可用 DIARY_DATA_ROOT 覆盖，默认 data，相对值基于版本目录；身份相对值基于版本目录的父目录。`SZD_COGNITIVE_CONFIG` 可指定另一份子服务配置。一般部署无需设置这些变量。

identity 文件缺失或损坏会明确报错，不自动生成新 ID，也不从业务数据中推断身份。公开 ID 用于识别，不是防仿冒签名。

## 搬迁与发布

搬迁服务器时复制“主页”及完整“深圳湾日记”部署，保留 `日记本/identity`、包含完整 data 的 `日记本/current` 和认知工作区自身的身份、代码、数据，保持相对结构，安装依赖并为运行账户配置环境变量。独立部署不需要复制“主页”。历史 archive 不是运行必需项。

发布开源项目时提供 identity 和版本代码，排除两套服务的真实 data、历史私有数据及密钥。新安装没有正式 data 时会创建空账号存储；未配置 OSS 时自动备份默认禁用。日记本 OSS 备份范围没有扩展到认知工作区，工作区数据需另行备份。
