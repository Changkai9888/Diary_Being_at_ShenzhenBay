# 深圳湾日记组身份与子服务配置

`service.json` 属于深圳湾日记整体项目，由日记本管理入口提供身份接口，位于版本与业务数据之外。普通升级时保留此目录，不用新版目录中的其他记录覆盖它。

- `service_id`：深圳湾日记整体的固定组 ID，当前为 `urn:uuid:c6e65645-aa71-479b-8f7e-fdd7e9efaeea`，与域名、端口、目录名称及业务版本无关。
- `service_name` 与 `service_role`：整体名称“深圳湾日记”及角色 `service-group`。
- `gateway_service_id` 与 `gateway_name`：管理入口的组件身份，保留原日记本 ID `urn:uuid:e56ef2d9-4867-48f7-8ab4-662de0a790c3`，名称为“日记本”。
- `identity_protocol`：身份接口协议，目前为 1。不是数据库结构版本，不随业务版本递增。

运行中的日记本版本读取此文件，通过 `GET /__service__/identity` 返回组身份、管理入口身份、下属服务挂载位置、就绪状态及自身业务版本。主站用自己部署配置中的预期组 ID、服务角色与层级能力核验 HTTP 响应，不修改此文件，也不从此文件自动更新预期值。原日记本 ID 只表示组件，不再作为整个组的预期 ID。

业务版本 `app_version` 和实际能力 `capabilities` 由版本代码维护，不写进固定身份记录。当前代码只支持身份协议 1，记录缺失、损坏或不兼容时启动失败；不会自动生成或使用隐藏的备用 ID。

`subservices.json` 是日记本管理认知工作区的部署配置，记录预期服务 ID、回环 origin、启动脚本和可选 Python。默认入口 `../../认知工作区/cognitive_workspace/server.py` 相对本目录解析；默认监听 `127.0.0.1:8766`。可通过 `SZD_COGNITIVE_CONFIG` 改用另一份配置。认知工作区自己的身份记录仍保留在其项目内，日记本通过 HTTP 核验它。

独立部署日记本同样保留此目录。默认布局是 `深圳湾日记/日记本/identity` 与 `深圳湾日记/日记本/current`（或 `日记本/t12`）；可通过 `DIARY_IDENTITY_DIR` 指定其他身份目录，相对值基于版本目录的父目录。此目录不得放在版本目录或业务数据目录内部。

公开 ID 可以随开源项目发布，但它是身份声明，不是密码或防仿冒签名。不同部署可以共享同一项目 ID；它不代表某一份用户数据库。
