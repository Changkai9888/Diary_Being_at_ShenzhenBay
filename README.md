# 深圳湾日记

Diary Being at Shenzhen Bay

深圳湾日记面向个人日常记录、精力安排、长期复盘与自我认知。项目从日记记录工具逐步发展为由“日记本”和“认知工作区”组成的个人工作系统，支持自行部署和保存数据。

当前发布版本为 **1.12.0**。本文对照仓库中的 **0.7.0** 说明本次主要变化，并列出后续开发方向；后续方向不代表当前已经实现。

- [上一公开版本：0.7.0](版本0.7.0/)

## 从 0.7.0 到 1.12.0 的主要变化

| 方面 | 0.7.0 | 1.12.0 |
| --- | --- | --- |
| 项目结构 | 以单个日记应用为主体 | 拆分为日记本管理入口和独立认知工作区，保留各自的服务身份、代码及数据目录 |
| 数据存储 | 基于表格文件保存日记 | 每用户 SQLite 保存每日记录；增加统一当前状态存储，并支持 Excel 导出 |
| 账号与数据 | 基础登录认证 | 增加网页注册、修改密码、用户目录隔离及登录失效后的页面保护 |
| 持续任务 | 每日记录为主 | 新增“在途任务”，与“待提升属性”共同保存跨日期的当前状态 |
| 计划与摘要 | 按日期填写 | 未保存日期显示它之前最近一个已保存日期的计划，保存后成为当天的独立记录 |
| AI 与认知 | 未包含独立认知工作区 | 增加工作区对话、全局统筹、带来源的共享认知与版本化记忆 |
| 备份 | 未包含当前 OSS 自动备份模块 | 增加定时快照、完整性校验、备份状态显示及结合数量与年龄的旧版本清理 |
| 页面操作 | 日记录入页面 | 整合置顶操作栏，增加服务切换、欢迎音频和适配手机及窄窗口的操作方式 |
| 发布与部署 | 早期应用目录 | 提供独立部署说明、通用配置示例、虚构示例账号初始化工具和离线回归用例 |

以下改进涵盖两个公开版本之间的演进，不表示每项都在同一天加入。月历、基础登录和每日记录等已有能力在新版中继续保留。

### 日记记录与长期状态

- **在途任务**：默认四行，可以垂直调整高度；和当日日记统一保存，内容作为当前状态延续，不每天复制一份。
- **待提升属性**：与在途任务统一保存在每用户 SQLite 的 `user_state` 表中；原有属性文本可按既定迁移逻辑导入。
- **计划与摘要**：只从所选日期之前向前查找最近的已保存记录，可跳过漏写的日期；没有来源时为空。读取只影响显示，点击保存才写入所选日期。已保存日期和已保存空白保持自身内容。
- **操作栏**：宽屏尽量使用一行；窄屏保留标题、导航和菜单，资产与保存作为主要操作，其他操作按空间展示或横向滚动。桌面窄窗口可通过鼠标滚动条访问溢出内容。
- **欢迎音频**：保留两份内置音频，新注册用户默认等权播放，可关闭声音。

### 独立的认知工作区

日记本承担账号、登录和服务入口管理，认知工作区承担对话与认知整理。用户从日记本顶部黄色标签进入工作区，通过工作区左上角蓝色图标返回；认知工作区也保留独立运行方式。

工作区包含常驻“全局统筹”、多个普通工作区、流式回复、按需查询历史、共享用户认知与带版本的摘要。用户原始对话与派生记忆分开保存，画像条目关联用户原话依据；同一登录用户的工作区可以按需只读查询其他工作区，不跨账号共享数据。

当前模型接入为 DeepSeek；需自行配置 `DEEPSEEK_API_KEY` 后才能生成回复。程序提供模型选择、调用用量与费用估算，并限制调用预算。当前不会自动把日记正文发送给模型；历史检索主要使用关键词和分页。

### 自动备份与数据边界

日记 OSS 备份在配置后运行：每天北京时间 04:00 调度，通过 SQLite 在线快照及文件校验生成 ZIP，再经上传和回读校验确认成功。开源默认配置关闭备份，部署者填写自己的存储位置和凭证。

旧版本清理使用**并且**关系：当前成功版本数大于 7，且最早版本严格超过 7×24 小时，才逐份删除。最近 7 天内的成功版本全部保留，同时至少保留最新 7 个成功版本；只有本次上传及将保留版本校验成功后才执行清理。

现有备份结构与范围保持独立：日记 OSS 快照覆盖日记 `user-data/`，不自动包含账号认证文件、音乐或认知工作区数据。这些内容需另外保管。详见[备份说明](版本1.12.0/日记本/current/OSS备份说明.md)。

## 当前版本怎样运行

**统一主入口：[版本1.12.0/日记本/current/app.py](版本1.12.0/日记本/current/app.py)。**

建议使用 Python 3.12。在克隆后的仓库根目录打开终端，执行：

```powershell
cd 版本1.12.0
python -m pip install -r 日记本/current/requirements.txt
python 日记本/current/app.py --host 127.0.0.1 --port 8081
```

访问 <http://127.0.0.1:8081/>。注册账号或按[当前版本说明](版本1.12.0/README.md)使用虚构示例用户。点击“认知工作区”时，日记本会核验并按需启动对应服务，默认仅监听本机 8766 端口。

```text
深圳湾日记
├─ 日记本：登录、日历、记录、资产、任务、备份与子服务管理
└─ 认知工作区：对话、全局统筹、历史查询与共享认知
```

独立使用本项目不需要外层主站。已有数据升级前请阅读[部署与数据迁移说明](版本1.12.0/新版部署与数据迁移说明.md)，保留完整原数据，不用示例数据覆盖正式部署。公开版本中的示例账号和空白工作区不包含原使用者的个人信息。

## 后续开发改进方向

下面是后续优先考虑的方向，尚未承诺完成时间；当前功能以代码与版本说明为准。

1. **降低记录成本**：继续改善手机、窄窗口和键盘操作，让日常记录、持续任务与回顾更顺畅；探索可由用户控制频率的录入提醒。
2. **让认知更准确、可纠正**：提高大量历史下的查询效果，改善不同画像条目之间的冲突处理、长期记忆容量及来源展示，便于用户检查与修正。
3. **按授权连接日记与认知**：探索由用户选择日期、字段和范围的日记引用与复盘能力。当前仍保持两套业务数据的明确边界，不默认读取或发送整本日记。
4. **完善数据可携带性与恢复**：在现有 Excel 导出基础上，规划 TXT、JSON 等导出方式，改善两套数据的迁移、恢复验证与部署文档。新增备份范围或改变格式前单独设计兼容方案。
5. **简化安装与服务维护**：完善首次配置、依赖检查、进程状态和停止服务的指引，继续验证账号隔离、保存一致性与服务身份匹配。
6. **逐步探索更多数据来源**：把跨设备同步、可穿戴设备数据接入及精力趋势回顾作为后续探索，先明确授权、数据格式和实际用途，再进入实现。

开发取向是让记录、回顾与认知讨论共同服务于长期自我管理，同时保持数据可掌握、功能边界清楚、日常操作负担可控。
